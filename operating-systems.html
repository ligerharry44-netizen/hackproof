Operating System

Program, Process, Thread

Program
A program is a file that contains instructions written in a programming language. It is stored on disk and is not running yet. Examples include Chrome, Notepad, or Python. A program becomes useful only when it is executed by the operating system.

Process
When a program starts running, it becomes a process. A process uses system resources like CPU, memory, files, and network. Each process has a unique Process ID (PID). Multiple processes can run at the same time in an operating system.

Thread
A thread is the smallest unit of execution inside a process. A process can have multiple threads running simultaneously. Threads share the same memory of the process but execute different tasks. Multithreading improves performance and responsiveness.

📌 Simple line:
Program is static, process is running, and thread is a part of a process.

Process States

When a process runs in an operating system, it does not run continuously. It moves through different states depending on CPU availability and input/output operations. These states help the OS manage multiple processes efficiently.

  • Ready: Process is ready and waiting for CPU.
  • Running: Process is currently executing.
  • Waiting: Process waiting for I/O like disk or keyboard.
  • Terminated: Process finished execution.

Context Switching

Context switching happens when the CPU switches from one process to another process. Since only one process can use the CPU at a time, the operating system quickly switches between processes to create the illusion of multitasking.

During context switching, the OS saves the current process state and loads the next process state. Too many context switches can slow down the system because switching takes time.

Memory Management

Memory management is the process of managing RAM and allocating memory to processes. The operating system decides how much memory each process gets and ensures processes do not access each other's memory.

Stack: Used for function calls and local variables.

Heap: Used for dynamic memory allocation during runtime.

Good memory management prevents memory leaks and improves system performance.

Virtual Memory

Virtual memory is a technique where the operating system uses disk space as extra memory when RAM is full. This allows the system to run large applications even if RAM is limited.

The OS moves inactive pages from RAM to disk (swap space) and brings them back when needed. This process is called paging or swapping.

User Mode vs Kernel Mode

Operating systems run in two modes for security and stability. User mode is used for normal applications, and kernel mode is used for OS core functions.

  • User Mode: Limited access to hardware and memory.
  • Kernel Mode: Full access to system hardware and memory.

If a program crashes in user mode, the system survives. If kernel crashes, the whole system crashes (BSOD / Kernel Panic).

File Permissions

File permissions control who can read, write, or execute a file. This is an important security feature in operating systems.

  • Read (r) – View file
  • Write (w) – Modify file
  • Execute (x) – Run file

Permissions are assigned to owner, group, and others. Proper permissions help protect sensitive files.

CPU Scheduling

CPU scheduling is the method used by the operating system to decide which process gets CPU time. Since many processes compete for CPU, scheduling ensures fairness and efficiency.

  • FCFS – First Come First Serve
  • Round Robin – Time slice for each process
  • Priority Scheduling

Deadlock

Deadlock happens when two or more processes are waiting for each other to release resources, and none of them can continue. As a result, the system gets stuck.

Deadlocks usually occur when processes hold resources and wait for other resources. Operating systems use prevention, avoidance, or detection methods to handle deadlocks.

Event Viewer :

A built-in Windows tool used to view system logs.

Helps troubleshoot errors, warnings, crashes, and security events.

alt="Windows Event Viewer Logs" class="diagram-img">

Logs are divided into:

  • Application – Software-related issues.
  • System – OS and hardware events.
  • Security – Login attempts, audits, policy changes.

Each event includes:

  • Event ID
  • Source
  • Severity (Information, Warning, Error, Critical)

Use cases :

  • Diagnosing system crashes (BSOD)
  • Investigating failed logins
  • Tracking software or driver failures

Registry :

A central hierarchical database storing Windows configuration settings.

Contains settings for:

  • Hardware
  • Installed software
  • User preferences
  • System policies

Important Registry hives:

  • HKEY_LOCAL_MACHINE (system-wide settings)
  • HKEY_CURRENT_USER (current user settings)
  • HKEY_CLASSES_ROOT (file associations)

Linux

Logs :

Plain text files that record system and application activity.

Stored mainly in /var/log/

alt="Linux Log Files in var log directory" class="diagram-img">

Common log files :

  • /var/log/syslog – General system activity
  • /var/log/auth.log – Authentication and sudo usage
  • /var/log/dmesg – Kernel messages
  • /var/log/boot.log – Boot process info

Viewing logs :

cat, less, tail

Permissions :

Linux uses a permission-based security model for files and directories.

Permission types:

  • r – read
  • w – write
  • x – execute

User categories:

  • Owner
  • Group
  • Others

Example:

-rwxr-xr--

  • Owner: read, write, execute
  • Group: read, execute
  • Others: read only

Commands :

  • ls -l
  • chmod
  • chown
